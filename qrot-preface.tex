  \noindent
  So you want to prove post-quantum security in the Random Oracle Model (ROM).

  Security proofs in the ROM enjoy a lot of advantages.
  	First, they usually support strong security claims.
  	Second, the results often achieve near-tightness, 
  	thereby enabling highly efficient constructions.
  	Lastly, they often are conceptually simple.
  	This is as close as one gets to a holy trinity for provable security.
  	In contrast, things are less simple in a world with quantum attackers --
  	if we want our security proofs to have merit in a post-quantum scenario, 
  	we have to revisit the ROM itself.
  	This is because random oracles model hash functions,
  	that is, publicly available algorithms that can be run by anyone
  	locally on their machine.
  	Nothing is stopping someone with a quantum computer to
  	boot it up and run it on a superposition of inputs.
  	If we want to accurately model quantum attackers, 
  	our model must thus reflect such strategies. 
  	This led to the development of the Quantum Random Oracle Model (QROM),
  	and it seems that our choice for arguing post-quantum security
  	is between the Standard Model and the QROM. 
  	Proofs in the Quantum Random Oracle Model (QROM), however,
  	can be notoriously hard to parse without specialized
  	knowledge in quantum information theory, and they often are infamously lossy.

  In the standard model, on the other hand,
  	superposition queries are no problem at all,
    since the standard model provides hash functions to attackers as-is.
    But even with a lot of the QROM proofs being lossy (so far),
    we note that when it comes to efficiency,
    Standard Model constructions nonetheless pale in comparison 
    with their (Q)ROM counterparts.
    (And, as every cryptographer knows, efficiency
    tends to trump security in the real world).

  As we inch ever closer to a point in time where cryptographically relevant
  	quantum computers might become more than a looming threat,
    we view it important to lower the barrier for security proofs in the QROM
    as much as possible, to help the community enable the post-quantum transition
    in a manner that is safe, efficient, and (provably) secure.
    One of the most important questions will be if and how far we can draw
    from the decades of experience with classical ROM proofs,
    and how to adapt classical proof strategies to quantum attackers.

  \paragraph{ROM Techniques Don't Transfer \ldots}
    As we will see through the proceedings of the tutorial,
      one of the most useful facts about the random oracle model
      is that anyone (including a security reduction)
      can efficiently \emph{simulate} a random oracle,
      simply by drawing its outputs upon request, one-at-a-time,
      and then storing them in an appropriate list for book-keeping.
      This technique, known as \emph{lazy sampling}, allows
      the reduction to implement the oracle efficiently.
      It also allows the reduction to see what input values the adversary is interested in.
      This property sometimes is called \emph{preimage awareness}.
      As we will see, preimage awareness will be very useful in security reductions
      because it gives the reduction valuable insights into the attacker's strategies.
      What's more, the random oracle allows the reduction to 
      \emph{adaptively reprogram} it on inputs of the reduction's choice.
      As we will see, adaptive reprogramming will also be very useful in security reductions
      because it gives the reduction the power to trick the attacker into behaviour
      that helps with relating security to the underlying hardness assumption.
      Indeed, much of the strength of the random oracle model lies in exactly
      these capabilities.

    None of this transfers directly to the case of quantum-accessible oracles.
      As just one example, think of lazy sampling and consider an adversary
      that queries the oracle on a superposition of all possible inputs all at once:
      to sample, respond on-the-fly and book-keep,
      the simulator would afterwards have to store an exponentially large list of input values!
      Besides the challenges surrounding storage, there's more --
      if the simulator already committed to all oracle output values
      just to be able to respond to the first query,
      then how would there be any room left for programming certain oracle outputs according to the reduction's needs?

  \paragraph{\ldots But the Concepts Do.}
    And yet, during the past decade the community has developed a plethora of techniques
      that recover most of these capabilities even in the presence of quantum attackers
      (albeit at a loss).
      Prime among these techniques are
      \begin{itemize}
      	\item the various \emph{One-Way to Hiding} (O2H) lemmas,
      		which allow for careful reprogramming of random oracle outputs as well as a
      		somewhat limited awareness of query inputs; 
      	
      	\item the Compressed Random Oracle (CRO) technique,
      		which allows one to efficiently simulate a quantum random oracle,
      		in direct analogy to classical ``lazy sampling'', and 	
      	\item Quantum Online-Extractability (QOE),
      		which -- as the name suggests -- allows for on-the-fly extraction of oracle inputs.
      \end{itemize}

    \autoref{part:classical}\khnote{Undefined} is all about the classical case. Here, we show
      several examples of security proofs in the random oracle model, all of
      which are conceptually simple and yield (relatively) tight security.
      The examples are lifted from the security proofs of two important
      transformations, the Fujisaki-Okamoto (FO) transformation (which transforms
      a weakly-secure public-key encryption scheme into a strongly-secure key
      encapsulation mechanism), and the Fiat-Shamir (FS) transformation (which
      transforms an interactive zero-knowledge protocol into a non-interactive
      signature scheme). 

    We meet these examples again in \autoref{part:tools}, where we use
      them to showcase the tools as we introduce them by showing that security
      holds also in the QROM, though usually with a security loss compared to the
      classical case, with the particular security loss depending on the tool used.
      \autoref{sec:o2h} is all about the One-way To Hiding (O2H) lemma, and its many variants: 
      how to use it to reprogram quantum random oracles, when to employ which
      version, and the impact of each version on the tightness of the proof. 
      Our running example here
      will be the second half of the FO transformation, known as the U-transform,
      and showing that if we start with a one-way secure (OW-CPA) deterministic PKE, we
      get an indistinguishable KEM secure against passive attacks (IND-CPA). 
      In \autoref{sec:extract}, we introduce the technique of
      Quantum Online-Extraction (QOE), and show how it can be used to prove
      that the U-transform \emph{also} upgrades to security against active attacks
      (IND-CCA).
      In \autoref{sec:adaptive}, we show how reprogramming can be made
      \emph{adaptive}, meaning that the reprogramming may now happen
      on-the-fly, on points that may (in full or in part) depend on
      adversarially-chosen input values. We use this to show
      how to go from a passively-secure Non-Interactive Zero-Knowledge (NIZK)
      protocol (such as constructed from a sigma protocol via the FS
      transformation) to an actively-secure signature scheme (EUF-CMA).
      Then, in \autoref{sec:compressed}, we delve into the details of 
      Compressed Random Oracles (CROs), and show how one might implement the
      technique to provide an efficient yet exact simulation of a quantum
      random oracle.
      This incredibly powerful technique takes some effort to wrap one's head
      around, and so we dedicate significant space to give gentle and
      intuitive explanations for all its moving parts, with several examples
      showing how queries are processed.
